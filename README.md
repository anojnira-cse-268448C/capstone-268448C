# capstone-268448C
This project explores how business users can query denormalized data-engineering models in plain English without bypassing application-level access controls. An LLM translates questions into SQL using a curated metadata layer (table and column descriptions, a business glossary, example queries). A policy layer written in my own code, not the LLM, then injects each user's access filters before execution. The warehouse is split into isolated PostgreSQL schemas: source, warehouse, access, metadata, llm_ops. The LLM-facing role can never read source or access data. The system is evaluated on execution accuracy, latency, cost and leakage under adversarial prompts. It is compared with a non-LLM baseline and naive prompting.

CS5998 Capstone, MSc Data Science & AI. All data is synthetic; no real PHI or PII is used.
